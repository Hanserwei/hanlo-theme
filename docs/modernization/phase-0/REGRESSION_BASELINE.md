# 阶段 0 回归基线规范

## 1. 基线目的

阶段 0 基线用于回答一个问题：后续构建、生命周期、模块化、依赖和 CSS 改造后，保留功能是否发生了非预期变化？

基线包含四部分：

1. 可复现环境和主题配置。
2. 核心页面截图。
3. 关键交互行为记录。
4. 安装包与浏览器资源数据。

截图不是全部证据。PJAX 重复绑定、评论加载、复制按钮、移动菜单、外部接口失败等问题必须通过行为记录补充。

| 场景 ID | 主题/插件状态 | 用途 |
| --- | --- | --- |

## 6. 截图采集规则

1. 使用同一浏览器版本、视口、DPR、字体和主题配置。
2. 清空或明确保留 localStorage；记录主题模式、侧栏和评论弹幕状态。
3. 等待字体、封面、懒加载图片、代码高亮和保留插件进入稳定状态。
4. 关闭光标闪烁、自动轮播、粒子、随机背景等非确定动画，或记录允许差异区域。
5. 截图前确认没有加载遮罩、骨架屏和未完成网络请求。
6. 对动态访问量、日期、随机推荐、评论时间等区域记录稳定策略。
7. 全页截图之外，文章代码区、评论区和移动菜单可增加局部截图。
8. 不用图片编辑器手工修补截图；若需遮盖敏感信息，记录原始文件和脱敏过程。

推荐命名：

```text
P0-BL-001__S0__P-home__desktop__light.webp
P0-BL-001__S2__P-post__mobile__dark.webp
```

截图清单至少包含文件名、SHA-256、路由、场景、浏览器、视口、主题模式和备注。

## 9. 静态基线复现命令

在仓库根目录执行：

```bash
rg --files templates | awk '
  BEGIN { html=0; js=0; css=0; other=0 }
  /\.html$/ { html++; next }
  /\.js$/ { js++; next }
  /\.css$/ { css++; next }
  { other++ }
  END { printf "html=%d js=%d css=%d other=%d total=%d\n", html, js, css, other, html+js+css+other }
'

find templates/assets -type f -printf '%s\n' |
  awk '{ total += $1; count += 1 } END { printf "files=%d bytes=%d\n", count, total }'

find templates/assets/libs -type f -printf '%s\n' |
  awk '{ total += $1; count += 1 } END { printf "vendor_files=%d vendor_bytes=%d\n", count, total }'

git archive --format=zip HEAD \
  theme.yaml settings.yaml annotation-setting.yaml templates |
  wc -c
```

P0-I6 应在最终阶段 0 提交上重新运行，并把变化原因写入迭代日志。
