# 阶段 0 执行计划

## 1. 执行顺序

阶段 0 按以下顺序推进：

```text
P0-I0 静态盘点与文档骨架
  → P0-I1 产品决策与兼容契约
  → P0-I2 删除前最小冒烟基线
  → P0-I3 分批删除已废弃功能
  → P0-I4 固化测试场景与数据
  → P0-I5 最终行为与视觉基线
  → P0-I6 资源基线与阶段审计
```

先采集 P0-I2 的轻量证据，是为了判断删除操作是否误伤核心页面；P0-I5 的完整截图必须在删除完成后采集，作为后续现代化工作的正式期望结果。

## 2. 通用执行约束

每轮迭代遵循以下规则：

1. 每次只允许一个明确目标，删除项按功能边界拆分，禁止一次移除所有候选能力。
2. 先更新决策表，再改代码；没有“已接受”决策的功能不得删除。
3. 一个删除项必须同时检查设置、模板、脚本、样式、图片、vendor 文件和文档。
4. 每次删除后都要生成主题 ZIP，并在目标 Halo 环境完成安装或升级验证。
5. 行为或视觉变化必须与本轮已接受的删除目标直接对应；其他差异视为回归。
6. 不修改阶段 1 范围的构建系统，不借机重构保留代码。
7. 每轮结束立即更新功能清单和迭代日志，不能等阶段结束后补记。

## 6. P0-I3：分批删除已废弃功能

**状态：已完成**

P0-I3 是一组短迭代，不是一个大提交。只有 P0-I1 中结论为“删除”的子项才执行。

### P0-I3.1：广告能力

候选范围：

- `settings.yaml` 的侧栏 `adbox` 选项与配置。
- `templates/modules/widgets/aside/adbox.html`。
- 各页面侧栏候选列表中的 `adbox`。
- 只服务于广告能力的样式、脚本和文档说明。

验收：配置界面不再出现广告选项，模板无 `adbox` 引用，首页/文章/分类/标签/页面侧栏正常。

### P0-I3.2：赞助与打赏能力

必须拆成两个独立决策和独立变更：

- 侧栏爱发电：`sidebar.power`、`aside/power.html`、爱发电接口与专属图片。
- 文章/关于页打赏：`aboutReward`、二维码、赞赏名单、文章底部打赏入口。

验收：只删除被明确确认的那一类；另一类若保留，行为不得改变。

### P0-I3.3：外部推广或社区入口

维护者已澄清“群聊/推广”指友链与开往：保留友链及其插件集成、互动友链和开往，删除微信公众号侧栏组件。

### P0-I3.4：可选视觉与交互能力

按已接受决策逐项处理 51LA、3D 分类、右键菜单、音乐子系统等。每项单独提交，避免资源归属交叉时无法回退。

### P0-I3.5：评论系统收敛

- 保留的评论实现先完成全场景冒烟。
- 逐个删除废弃 provider 的设置、模板、适配脚本、vendor 文件、最近评论分支和弹幕分支。
- 不在本轮重写保留 provider。

## 10. 分支、提交和回退建议

建议使用短分支，例如：

```text
docs/phase-0-baseline-plan
chore/remove-sidebar-ads
chore/remove-afdian-widget
chore/drop-unused-comment-provider
test/capture-phase-0-baseline
```

每个删除提交必须可独立回退。回退时恢复该提交删除的设置、模板和资源整体，禁止只恢复模板而遗漏配置或 vendor 文件。若删除后真实 Halo 验证失败，应先回退该子迭代，再根据日志重新缩小范围。
