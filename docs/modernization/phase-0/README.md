# 阶段 0：功能盘点与回归基线

## 1. 文档定位

这里是 [`MODERNIZATION_ROADMAP.md`](../../MODERNIZATION_ROADMAP.md) 阶段 0 的唯一执行入口。路线图说明“为什么做”和“最终走向”，本目录负责记录“按什么顺序做、每轮交付什么、依据是什么、谁来确认、如何验收和回退”。

阶段 0 当前状态为 **进行中（实施与验收已完成，等待提交）**。P0-I0 至 P0-I6 的工作树交付物和证据已经完成；按照路线图维护约定，只有提交或合并到 `master` 后才把路线图状态改为“已完成”。

## 2. 阶段目标

在引入 Vite、TypeScript、模块化和大规模样式调整前，完成以下结果：

1. 每项用户可见能力都有“保留、重写、可选、删除”中的明确结论。
2. 已确认删除的能力不再残留设置项、模板、脚本、样式或专属资源。
3. Halo 最低版本、浏览器范围、插件组合和测试数据成为明确兼容契约。
4. 核心页面具有可重复的桌面端、移动端、浅色和深色行为与视觉基线。
5. 当前主题安装包和关键页面资源开销有可比较的数据记录。
6. 阶段 1 可以直接使用这里的基线判断是否出现非预期回归。

## 3. 本阶段不做什么

- 不引入 Vite、TypeScript、pnpm 或新的构建目录；这些属于阶段 1。
- 不重写 PJAX、评论、音乐、代码高亮或 CSS；本阶段只决定去留并删除明确废弃项。
- 不以“顺手优化”为由改变保留功能的视觉或交互。
- 不在没有决策记录和回归证据时删除看似未使用的资源。
- 不把截图基线等同于自动化视觉测试；自动化接入属于后续阶段。

## 7. 角色与决策规则

- **仓库维护者**：确认产品范围、兼容范围、评论系统、截图存储方式和测试环境；默认负责人为本仓库维护者。
- **实施者**：完成代码盘点、删除、验证、证据整理和文档更新。
- **决策状态**：只有在[决策登记表](DECISION_REGISTER.md)中标记为“已接受”的结论才允许触发功能删除。
- **证据优先级**：真实 Halo 环境结果 > 构建或安装结果 > 静态引用检查 > 主观判断。
