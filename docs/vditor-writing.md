# Hanlo + Vditor 书写与渲染说明

适用于 Hanlo 2.7.2，以及 `halo-plugin-vditor`（插件标识 `vditor-mde`）。

[完整测试文章](examples/vditor-render-demo.md) 可以整篇复制到 Vditor 的 Markdown 源码模式中保存，用于安装主题后的实机验收。[全部高亮语言与别名](shiki-languages.md) 来自主题固定的 Shiki 4.4.3 注册表。

## 使用前确认

- 在 Halo 的主题设置中启用「代码 → 启用代码语法高亮」，按需启用复制、行号、折叠等工具。
- 文章使用 Vditor 编辑并保存。主题通过插件注入的 `vditor-article-sign` 标识识别正文，也适用于 Vditor 独立页面。
- 保持 Vditor 插件的前台渲染启用。主题复用插件的渲染器和资源地址，不重复引入另一套 Mermaid、KaTeX 或 ECharts。
- 当前插件仓库的前台方法包为 Vditor **3.11.3**，而 `render-utils.js` 中默认 CDN 常量仍为 **3.9.9**。如果你没有另外配置资源地址，建议在插件设置中使用可访问的 `https://cdn.jsdelivr.net/npm/vditor@3.11.3` 或对应版本的自托管目录，以免方法与图表资源版本不一致。主题不会修改插件配置。
- 主题以 HTML 的 `data-theme` 为准同步插件亮暗状态；插件即使设置为跟随系统，也不会在页面亮色时强制使用暗色图表。

## 推荐语法

代码块的三个反引号后面写**语言标识**，标识后换行再写内容。标识用小写，不要写成展示名称，例如用 `javascript`，不用 `JavaScript 代码`。

| 内容 | 推荐写法 | 注意事项 |
| --- | --- | --- |
| 正文层级与大纲 | `## 二级标题`、`### 三级标题` | 正文从二级标题开始；文章标题已由主题显示。使用真实 Markdown 标题，主题目录读取 h1–h6。 |
| 标题锚点 | 使用标题生成的链接 | 不依赖 `{#custom-id}`，不同解析器对该扩展支持不一致；需要稳定 ID 时可插入 `<a id="my-section"></a>`，再写 `[跳转](#my-section)`。 |
| 行内公式 | `$e^{i\pi}+1=0$` | `$` 紧贴公式，避免金额或普通文字被误识别。 |
| 独立公式 | 各占一行的 `$$` 包住 LaTeX 内容 | 推荐 KaTeX 支持的语法。公式字体和字号交给数学引擎，不给公式强制指定白色或黑色。 |
| 脑图 | `mindmap` 围栏中的缩进 Markdown 列表 | Vditor 会把列表转换成脑图数据，不要把普通 JSON 直接塞进该围栏。缩进用空格，节点名称保持简短。 |
| 另一种脑图 | `markmap` 围栏中的标题或列表 | 用于需要 Markmap 展示方式的内容，取决于插件相应资源是否可用。 |
| 图表 | `echarts` 围栏中的 JSON 配置 | 推荐严格 JSON：双引号，无注释、尾逗号或函数。省略背景、文字和坐标轴颜色，让配色随亮暗主题切换；自定义数据系列颜色可以保留。 |
| 流程图 | `mermaid` 围栏中的 `graph TD` / `flowchart LR` | 优先 Mermaid。节点 ID 用简短英文，中文文字放在引号中，如 `A["开始"]`。 |
| 甘特图 | `mermaid` 围栏中的 `gantt` | 使用 `dateFormat YYYY-MM-DD`，时间段不要过长。大图保留可读字号，通过容器横向滚动查看。 |
| 时序图 | `mermaid` 围栏中的 `sequenceDiagram` | 中文名称用 `participant User as 用户`，消息文本直接写中文。 |
| 五线谱 | `abc` 围栏 | 使用 ABC 记谱法，提供 `X:`、`T:`、`M:`、`L:`、`K:`；主题让谱线和音符随正文颜色切换。 |
| Graphviz | `graphviz` 围栏中的 DOT | `digraph` 表示有向图。指定 `style=filled` 时同时给出 `fillcolor` 和可读的 `fontcolor`，避免默认黑色填充配黑字。 |
| PlantUML | `plantuml` 围栏中的 `@startuml`…`@enduml` | 当前插件把内容编码后交给 `www.plantuml.com` 生成 SVG，需要外网；图片内的颜色由 PlantUML 决定。 |
| 旧式流程图 | `flowchart` 围栏中的 flowchart.js 语法 | 与 Mermaid 是两个语法系统，不能把 `graph TD` 写进 `flowchart` 围栏。新内容推荐 Mermaid。 |
| 普通代码 | `java`、`rust`、`go`、`python` 等围栏 | 支持 Shiki 全部 242 种语言及别名，语法文件按需从主题自身资源加载。 |
| 纯文本 | `text`、`txt`、`plain`、`plaintext` 或无标识围栏 | 与普通代码共用亮暗代码框、行号、复制与折叠工具，文字不做语法着色；未知语言也使用纯文本代码框。 |
| 图片 | `![说明](附件地址)` | 推荐使用 Halo 附件地址与替代文本。 |
| 音视频 | `<video controls src="…"></video>` / `<audio controls src="…"></audio>` | 原生控件比较稳定；使用真实可访问的附件 URL。独立媒体链接的自动转换还需要插件启用「媒体渲染」。 |
| 平台视频 | Vditor 支持的平台链接，或平台提供的 iframe | 是否可嵌入由视频平台决定；主题只处理容器布局。 |

公式、Mermaid、ECharts、mindmap、markmap、ABC、Graphviz、Flowchart、PlantUML 都是**特殊渲染围栏**，主题会让 Shiki 跳过它们。想展示这些语言的源码而不生成图表，使用 `text` 围栏。

2.6.1 起，代码框显示时会忽略一个末尾行结束符，避免 Markdown 产生的结束换行多显示一个空行及行号。有意保留的额外空行、缩进和行末空格不受影响；复制按钮仍复制完整原文（包括末尾换行）。

## 亮暗模式的边界

- Mermaid、ECharts、mindmap 会根据当前模式重新渲染。主题在第一次渲染前保留源码，切换时释放旧图表实例。每一张图独立等待自己的上一轮渲染结束后再应用最新状态，未完成的图不会阻塞其它图。
- ECharts 没有显式 `backgroundColor` 时使用主题画布；明确写入的背景颜色会保留。标题、坐标轴文字、网格线等如果自行指定颜色，也需要作者自行保证可读性。
- mindmap 的标签和连接线跟随主题；布局变化时 ECharts 实例会调整尺寸。
- Mermaid 标签恢复图表所需的排版，避免正文段落外边距导致中文标签被裁切。宽图不强行压缩成难以阅读的小字；键盘可聚焦图表区域并横向滚动。
- Mermaid 推荐纯文本标签，不在图定义中指定固定 `theme`、`themeVariables` 或通过 HTML 样式强制文字颜色。主题重绘采用 Mermaid 的 strict 模式，不支持在图内执行脚本或点击回调。
- ABC 谱线随正文颜色切换。Graphviz 的原始填充色不再被插件暗色样式统一改成蓝色。
- **Graphviz、旧式 Flowchart、PlantUML 保持浅色画布**，以保证固定黑字和作者指定的颜色能读清楚；它们的外围卡片仍跟随主题。主题不对 SVG 或远程图像进行整体反色。
- 语音阅读不是 Markdown 语法。虽然 Vditor 库具有语音接口，当前插件的前台 `render-utils.js` 并没有调用 `speechRender`，本次主题适配也没有增加朗读按钮。编辑器内的语音能力不等于公开文章自动具备朗读入口；公开文章可使用浏览器的朗读功能。
- 编辑器的大纲面板不会作为正文发布；公开页面的目录来自主题。无需在文中再写 `[toc]` 来复制一份主题目录。

## 简繁转换与首次加载

2.7.0 使用随主题打包的 **opencc-js 1.4.2**，从原始内容进行词组转换。简体原文转换为台湾繁体字形（`cn → tw`），繁体原文转换为简体（`tw → cn`）；不启用台湾词汇替换模式 `twp`。同页切回原文时直接恢复缓存原文，不依赖简繁反向转换，因此不会把「皇后」等有歧义的文字改坏。

- 点击切换后，PlantUML 用转换后的原始源码立即更新 SVG 出图地址，不需要刷新页面；新的图片仍需等待远程服务返回。重复切回同一份内容会使用相同 URL，能否命中缓存由浏览器和服务端缓存策略决定。
- Mermaid、ECharts、mindmap、Graphviz、Flowchart、ABC、Markmap 也从保留的源码响应切换。数学公式、普通代码、纯文本代码框、可编辑内容及表单值不转换，复制代码与原文保持一致。
- Markmap 在稳定的容器中更新同一个实例。2.7.2 修复其上游脚本附带 Prism 自动高亮的冲突：脚本在执行前标记为 `data-manual`，避免整页扫描把 SVG 改写为 CSS 和节点文字，也保护旁边 Shiki 的行号与配色。重复调用只使用第一次保存的 Markdown，不再从生成后的图形读取源码；连续切换不会叠加多张图，离页会释放实例。
- `translate="no"`、`.notranslate` 和 `.ignore-opencc` 可保护一个区域不转换。链接地址、图片地址和标题锚点 ID 不会修改；提示文字、图片替代文本和无障碍标签会转换。后续出现的评论等内容也会按当前模式处理。
- 图表 ID 推荐英文，展示文字使用中文。ECharts 推荐 JSON，主题保留对象键和与键匹配的字段引用，只转换可转换字符串；URL 保留原值。
- 原始网页不会被改写到数据库。访客选择保留原来的两天存储规则；页面 `lang` 使用 `zh-Hans` / `zh-Hant` 表示实际字形。

原实现是简单的逐字映射和全页 DOM 改写，无法处理一对多字形、动态绘图或跨域 SVG。不存在一个强制适用所有网站的“简繁转换行业标准”；OpenCC 是成熟的开源实现，使用词组词典、保存原文、尊重 HTML 不转换标记、让图形从数据重新渲染，更符合常见的工程做法。自动转换仍需人工校对，不能等同于人工维护的地域用词和完整多语言页面。

原加载顺序是“整页 load → 加载绘图库 → 计算图形”，PlantUML 还会经历“加载编码器 → 请求在线 SVG”。2.7.0 在正文 DOM 就绪、主题拿到插件接口后启动，不等其它图片和媒体全部加载；首次只在访客已选择另一种字形时等待本地转换词典，以确保第一张图就是正确字形。仅为文章实际需要的 CDN/PlantUML 域名提前建立连接；保留插件的按需加载，不给没有图表的页面下载全部绘图库。

重绘不再每次扫描整个正文 SVG，ECharts 动画和无关 DOM 更新也不会触发全文扫描；Graphviz 的语言重绘在完成或离页后释放工作线程。网络速度、大型图的布局计算、PlantUML 远程出图耗时仍然存在。最终加速幅度需在实际浏览器网络环境下确认，本地静态和模拟测试不作为网络测速结论。

参考：[OpenCC JavaScript 文档](https://github.com/nk2028/opencc-js)、[HTML translate 属性](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/translate)、[BCP 47 语言标签](https://www.w3.org/International/articles/bcp47/)。

## 全语言 Shiki 的取舍

此前主题预置了 18 个标识：`bash`、`cpp`、`csharp`、`css`、`dockerfile`、`html`、`java`、`javascript`、`json`、`jsx`、`markdown`、`python`、`shellscript`、`sql`、`tsx`、`typescript`、`vue`、`yaml`。`bash` 和 `shellscript` 对应同一类 Shell 语法。XML 曾借用 HTML 语法，现在使用真正的 XML 语法。

2.6.0 开放 Shiki 4.4.3 的全部 242 种语言、104 个官方别名，并保留 `c++`、`c#`、`htm`、`shell`、`vue-html` 等兼容写法。六种原有配色保持可用。

实现采用本地动态导入，先初始化空语言的高亮器，再加载本篇使用的语言及其依赖；并发请求同一种语言会合并。正则引擎使用 Oniguruma，以覆盖完整 TextMate 语法。没有普通代码或纯文本代码框的页面不会初始化高亮引擎。纯文本复用同一套渲染与配色，不加载语言语法文件。

代价是主题包增加许多语法资源文件，部署体积和文件数量会上升。读者首次遇到某种语言时需额外下载语法；包含大量不同语言、长行或巨型代码块的文章仍会有 CPU 和内存成本。**开放所有语言不代表每篇文章下载所有语言**，也不自动识别未标注的代码。这里的「全部」指当前固定版本注册表中的语言，不包括任意私有语法。

## 安装后实机验收

1. 把[测试文章](examples/vditor-render-demo.md)粘贴到 Vditor 源码模式，替换音视频附件占位地址，保存并预览。
2. 分别在亮色和暗色状态刷新页面；检查图表不是沿用上次模式的配色。
3. 在同一页面连续切换亮→暗→亮，核对公式、脑图、图表、流程图、甘特图、时序图与五线谱内容完整。
4. 检查 Graphviz 节点文字和固定浅色画布；PlantUML 在网络可用时生成图像。
5. 缩小窗口或在手机上检查宽图可横向滚动，ECharts 宽度会适配，页面本身不出现整页横向溢出。
6. 核对 Rust、Go、XML、Java 的高亮、复制、行号与折叠，以及 `text`、无标识围栏的同款代码框；浅色 One Light 应为浅色背景，切到暗色后背景和文字一起切换。代码末尾没有额外的空白行号，复制内容仍为原始代码，不包含行号和按钮文案。
7. 连续简→繁→简切换，核对 PlantUML 无需刷新即可更新，其它图表、目录与正文同步，代码和公式不变。检查「头发、开发、皇后、后台」等词及动态出现的内容；第 11 节 Markmap 的「手机阅读」应随切换变为「手機閱讀」，再切回恢复原文，版权卡片右侧不应出现缺字方框。
8. 从文章跳走再通过浏览器返回，确认图表和工具仍工作；在网络面板观察绘图库请求早于其它慢速图片的完成时间，控制台不持续出现重复渲染、重复初始化或脚本加载错误。

本地自动检查验证类型、语法加载、资源打包和模拟的页面生命周期；最终图形排版、插件设置与实际网络环境由实机验收确认。

开发者可以执行 `pnpm test:markmap-runtime` 额外验证实际的 Vditor Markmap 整包脚本（包括附带的 D3、Transformer 和 Prism）。命令首次下载固定版本并检查 SHA-256，之后使用 `build/markmap-runtime` 下的缓存；测试在提供固定几何尺寸的离线 DOM 中复现旧版 SVG 被替换的问题，再检查主题加载器、实际绘图、简繁往返及 Shiki 标记的保留。此命令独立于不依赖网络下载的常规单元测试，不代表浏览器视觉验收。
